# New Relic Connector — Preparation

**Category:** C42. Observability & APM  
**Status:** App Preparation Complete (Genuinely Vendor-Specific)  
**Standard:** APP_PREPARATION_STANDARD.md

## 1. Паспорт коннектора
- **Название:** New Relic Connector (`new-relic-connector`)
- **Официальный портал вендора:** https://newrelic.com
- **Базовый API:** `https://api.newrelic.com/v2`
- **Модель аутентификации:** User API Key (NRAK) / GraphQL NerdGraph API
- **Назначение:** Интеграция платформы Imperal Cloud с New Relic для автоматизации предметной области: глубокий анализ производительности бэкенд-сервисов, задержек транзакций БД и ошибок распределенных микросервисов.

## 2. Решаемая проблема
Когда **Backend-разработчик** сталкивается с задачей **глубокий анализ производительности бэкенд-сервисов, задержек транзакций БД и ошибок распределенных микросервисов**, возникает необходимость ручного мониторинга, дублирования статусов и переключения между окнами. Это приводит к потере времени, замедлению реакции на инциденты и ошибкам ручного ввода.

## 3. Роли и права доступа
- **Backend-разработчик, архитектурный инженер, системный администратор**
- Принцип наименьших привилегий (Least Privilege): токен запрашивает доступ только к разрешенным операциям чтения и подтвержденным действиям.

## 4. Ключевые сущности
приложения APM (/applications.json), алерты (/alerts_policies.json), NerdGraph запросы (/graphql), метрики серверов

## 5. Первичный рабочий сценарий
`запрос метрик задержки и частоты ошибок (throughput/error rate) -> получение списка сработавших политик алертов`.

## 6. Границы коннектора
- Изолированное хранение секретов (BYOC).
- Никаких фиктивных методов сторонних предметных областей.
- Деструктивные операции требуют явного подтверждения пользователя.
